## 2. Colony health classifier

`ml/train_health.py` → `ml/models/health_clf.joblib`, served by
`apps/api/aurabee_api/health.py`.

### Results on a completely separate simulation run

Different hives, different seed, different weather — no hive appears in both
sets.

```
              precision    recall  f1-score   support
     healthy      0.983     0.982     0.983     85198
   pre_swarm      0.991     0.989     0.990      6751
   queenless      0.959     0.981     0.970     27038
     robbing      1.000     0.972     0.986       108
  starvation      1.000     0.551     0.711       787
      varroa      0.624     0.510     0.561      1540
    wax_moth      0.000     0.000     0.000         0

    accuracy                          0.974    121422
```

**Read this honestly.** Accuracy of 0.974 is the least interesting number on
the page — the set is 70% healthy, so predicting "healthy" always would score
0.70. What matters:

- **queenless recall 0.981** — the flagship case, and it holds up.
- **pre_swarm 0.989** — swarm prediction is genuinely strong.
- **varroa recall 0.510** — the model misses half of them. Varroa is a
  three-week decline that looks like "slightly less healthy"; 715 of 1,540
  varroa samples were called healthy. This is a real weakness, not a rounding
  error, and it is why the alerting layer demands 0.88 confidence before varroa
  is allowed to interrupt anyone.
- **starvation precision 1.000, recall 0.551** — when it speaks it is right,
  but it stays quiet half the time.
- **wax_moth has zero support in the test run**, so its 0.000 is meaningless
  and it drags macro F1 down artificially. Macro F1 of 0.743 should be read as
  ~0.87 across the classes that actually occur.

### Evaluation rules that are not optional

**Split by hive, never by row.** Consecutive hourly frames from one colony are
near-duplicates; a random row split puts almost-identical rows on both sides
and produces a fake 99% that collapses on a new hive.

**A separate simulation run as the test set.** Held-out hives from the *same*
run share weather. The reported numbers come from an independent run with a
different seed.

## 3. Which sensors actually earn their place

`ml/ablation.py`. This overturned a conclusion we had already drawn, which is
why it is worth recording.

| Sensor set | macro F1 | accuracy | queenless | varroa | pre_swarm |
|---|---|---|---|---|---|
| everything | **0.748** | 0.975 | 0.983 | 0.531 | 0.990 |
| no microphone | 0.483 | 0.929 | 0.979 | 0.223 | **0.365** |
| no load cell | 0.739 | 0.955 | 0.905 | 0.620 | 0.988 |
| no thermometers | 0.710 | 0.970 | 0.987 | 0.247 | 0.990 |
| scale + thermometer only | 0.477 | 0.927 | 0.978 | 0.223 | 0.326 |
| **microphone only** | 0.693 | 0.935 | 0.925 | 0.013 | 0.990 |
| scale only | 0.433 | 0.909 | 0.948 | 0.118 | 0.426 |

**The microphone is the highest-value single sensor**, and swarm prediction is
almost entirely acoustic (0.990 → 0.365 without it, costing 0.265 macro F1).
Do not cut it from the BOM to save cost. The table above is copied from
[`metrics/sensor_ablation.json`](../metrics/sensor_ablation.json), regenerated
by `python ml/ablation.py`.

**Permutation importance said the opposite and was wrong.** It ranked
`weight_chg_7d` and `weight_chg_24h` on top and put acoustic features far below,
because the 33 acoustic features are correlated — permuting one at a time barely
moves the score while the other 32 carry the same information. Ablation by
sensor *group* is the honest measurement. This is a standard trap and we walked
straight into it.

**Queenlessness is robust to losing any single sensor** (0.90–0.99 across all
ablations) because both the thermal decouple and the acoustic bimodality carry
it independently. That redundancy is a deployment argument: a hive with a failed
microphone still detects the most important fault.

## 4. Yield forecaster

`ml/train_yield.py` → `ml/models/yield_p{10,50,90}.joblib`.

Three quantile regressors trained with pinball loss. **The P90 becomes the
on-chain mint ceiling**, so this is the one model whose error costs a real
person money.

### The asymmetry that shapes it

- **P90 too low** → an honest beekeeper is blocked from selling their own
  honey. They lose income and abandon the system. This is the failure that ends
  adoption.
- **P90 too high** → some fraud passes, and the chemical testing ladder is the
  next line of defence.

The ceiling is deliberately generous. Mean headroom above actual yield is +45%.

### Conformal calibration, and why it was needed

A nominal 0.9 quantile is **not** a 90% ceiling. First fit:

```
P90 covered 74.6% of actual yields
```

A quarter of honest beekeepers would have been blocked. Two fixes, applied in
order:

1. **Train across multiple weather realisations.** The first attempt at
   conformal calibration returned a factor of exactly 1.000 and did nothing —
   because the calibration hives shared a seed, and therefore weather, with the
   fit hives, while the test run did not. **Conformal guarantees require
   exchangeability, and a different weather seed breaks it.** Training on four
   independent runs (135 hives) fixed the underlying generalisation gap.
2. **Then calibrate empirically.** On hives the model never saw, take the 90th
   percentile of actual/predicted and scale the ceiling by it.

```
fit 298 windows / calibration 99 windows
conformal factor: x1.033
coverage before calibration: 91.5%
coverage after:             100.0%
P50 median absolute error:    0.61 kg
```

100% on 59 test windows is consistent with true coverage anywhere above ~95%;
it is not evidence of perfection, just of erring in the safe direction.

## 5. Alerting: why the model is not wired straight to notifications

`apps/api/aurabee_api/health.py`. A beekeeper who walks 3 km to a hive that
turns out to be fine stops trusting the app, and an app they do not trust is
worse than none.

- **Persistence** — a state must hold across ≥60% of a 24-sample window.
- **Per-class confidence floors**, set from the model's own measured precision:
  `queenless` 0.70, `varroa` 0.88, `wax_moth` 0.90. The classes the model is
  worst at have to be more certain before they interrupt someone.
- **Deduplication** — an open unacknowledged alert of the same type is not
  raised again.
- **Advice, not class names.** The payload carries a sentence in Hindi and
  English. `varroa` never reaches a person.

Verified on stored telemetry: of 8 sentinel hives, the model found exactly the
two with injected faults — `HN-UP-SIT-0003` queenless (confidence 1.000) and
`HN-UP-SIT-0007` dead (its varroa scenario killed it). A third hive scored
varroa at 0.844 and was **correctly held back** below the 0.88 floor.

## 5b. Anomaly detector

`ml/train_anomaly.py`. Fitted on **healthy windows only**, so it answers a
different question from the classifier: *how far is this from any normal hive I
have seen?* That is what catches a fault nobody labelled -- a drifting load
cell, a node someone moved.

AUC per fault class, on the separate test run:

| fault | AUC | verdict |
|---|---|---|
| robbing | 0.997 | strong |
| pre_swarm | 0.951 | strong |
| queenless | 0.913 | strong |
| starvation | 0.784 | useful |
| varroa | 0.619 | weak |

Threshold set at the 99th percentile of the *healthy* distribution -- not tuned
against known faults, because in the field there is no label to tune against and
a threshold fitted to known faults would not survive an unknown one. That gives
a 1.0% false-alarm rate.

Varroa is weak here too, consistently with the classifier. Two independent
methods agreeing that varroa is hard is more informative than either alone.

## 5c. Varroa counter

`apps/api/aurabee_api/varroa.py`. **Classical computer vision, not a trained
detector**, because there is no annotated Indian sticky-board dataset and a
model trained on European boards would carry a domain gap we could not measure.

A mite is a dark, near-elliptical body about 1.1 x 1.6 mm on a deliberately
white board. Adaptive thresholding plus connected components filtered on area,
aspect ratio and solidity exploits that geometry, and every rejection is
explainable (`too_large`, `wrong_shape`, `too_ragged`).

Mean relative error against synthetic boards with known counts: **12.5%**,
slightly undercounting because overlapping mites merge into one too-large blob.
The live figure is in [`metrics/varroa_counter.json`](../metrics/varroa_counter.json).

Two bugs found while building it, both worth recording:

- **The resize was destroying the measurement.** A fixed 1400 px cap turned a
  43 cm board into 3.3 px/mm, making every mite three pixels wide. The target
  resolution is now derived from the physical board width.
- **A blurred photo returned "no mites found" at 0.85 confidence.** That is the
  most dangerous possible output: the beekeeper concludes the colony is clean
  and does not treat. A Laplacian-variance sharpness gate now refuses instead.

## 6. Datasets

| File | Contents |
|---|---|
| `ml/datasets/train_v1.csv` | 45 hives, 260 days, seed 11 |
| `ml/datasets/run_s{23,37,51}.csv` | 30 hives each, independent weather |
| `ml/datasets/train_v2.csv` | the four concatenated — 821,448 rows, 135 hives |
| `ml/datasets/holdout_v1.csv` | 20 hives, seed 777, never trained on |

Node ids are namespaced per run (`HN-…@r2`) so the hive-level split cannot leak
across runs.

### The simulator needed a beekeeper before any of this worked

The first dataset had **33% of samples labelled `dead` and 39 of 45 hives dead
by the end** — because the simulator modelled faults with no management. Nobody
fed a starving colony, treated mites or requeened, so every fault ran to death.

That is not an apiary anyone would still own, and a model trained on it learns
that faults are terminal. `Colony.beekeeper_visit()` now inspects every ~11
days with *imperfect* detection, and loss fell to a realistic ~9% per year with
faults appearing as episodes.

Public datasets remain the right next step for real-world grounding — Zenodo
*To bee or not to bee*, Kaggle *Smart Bee Colony Monitor*, TFDS `bee_dataset`,
UrBAN — see [09-research.md](09-research.md).

## 7. The caveat that goes on every number here

**Everything above is measured on simulated hives.** It shows the models learned
the physics the simulator encodes. It is **not** evidence they work on real
bees, and publishing simulator accuracy as field accuracy would be dishonest.

Two specific gaps:

- Most public bee acoustics are *Apis mellifera*. *Apis cerana indica*, common
  in Indian beekeeping, is acoustically different and has no public dataset.
- The yield P90 is an on-chain ceiling. Before any real deployment it must be
  refitted on measured harvests from the target district — a ceiling calibrated
  on a simulator would block real beekeepers.

Both `health_clf.meta.json` and `yield.meta.json` carry this caveat in the
artefact itself, so it travels with the model rather than living only here.
